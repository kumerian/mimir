# Agile process

These documents are a proposed starting agreement for developing Mimir. The repository has a Markdown backlog and automated checks, but does not yet record a sprint cadence, Scrum events, or assigned team roles. The team should review the proposal, make any needed decisions, and update it as its working agreements evolve.

The Definition of Ready and Definition of Undone are local aids, not required Scrum artifacts. Scrum does not prescribe either one. The Definition of Done is the team's shared quality bar; this initial version reflects the current repository and is expected to evolve with the product.

## Documents

- [Working process](working-process.md): how work moves from the backlog through completion.
- [Definition of Ready](definition-of-ready.md): a checklist for deciding whether work can be started.
- [Definition of Done](definition-of-done.md): the completion criteria for changes.
- [Definition of Undone](definition-of-undone.md): how to handle work that cannot yet meet the Definition of Done.

## Decisions to revisit

No iteration length, regular event schedule, product-owner assignment, or review-approval rule is established in the repository. The team can agree on these separately; this initial process does not assume them.

The [process backlog](../backlog/process/README.md) calls for each feature to improve the Definition of Done. Update the definition when a feature delivers new shared quality practices, and distinguish implemented practices from future proposals.
